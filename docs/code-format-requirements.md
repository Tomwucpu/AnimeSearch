# 代码格式要求文档

本文档适用于本项目后续所有代码编写、修改和整理工作。后续新增代码必须优先遵循本文件，其次遵循项目现有代码风格。

## 1. 通用要求

- 代码保持简洁、清晰、可读，不写无意义的复杂抽象。
- 文件、函数、变量命名要表达真实用途。
- 不提交无关改动，不随意重构与当前任务无关的文件。
- 不保留调试用 `console.log`，除非明确用于启动日志或错误排查。
- 中文页面文案必须统一、自然，不混用不必要的英文。
- 注释只写在复杂逻辑前，解释“为什么这样做”，不解释显而易见的代码。

## 2. 目录规范

公共代码必须单独放置，减少页面内重复代码。

```text
api/          接口请求封装
components/   可复用组件
pages/        页面
stores/       Pinia 状态管理
utils/        工具函数
static/       静态资源
tests/        自动化测试
```

页面不得直接重复大量请求逻辑；可复用逻辑优先放到 `api/`、`stores/` 或 `utils/`。

## 3. Vue / UniApp 组件规范

- Vue 页面和组件优先使用 `<script setup>`。
- 页面负责业务流程，组件负责展示和事件。
- 组件必须通过 `props` 接收数据，通过 `emit` 抛出事件。
- 组件内部不直接请求接口，除非该组件本身就是独立业务模块。
- 用户可见文案使用中文。
- 点击跳转统一使用 `uni.navigateTo` 或 tabBar 对应跳转方式。
- 图片预览统一使用 `uni.previewImage`。

组件基本结构：

```vue
<template>
  <view></view>
</template>

<script setup>
</script>

<style scoped>
</style>
```

## 4. JavaScript 规范

- 使用 ES Module：`import` / `export`。
- 优先使用 `const`，需要重新赋值时才使用 `let`。
- 不使用 `var`。
- 异步接口统一使用 `async/await`。
- 捕获异常后给出用户可理解的中文提示。
- 工具函数保持纯净，避免依赖页面状态。
- 对接口返回数据先归一化，再交给页面和组件使用。

示例：

```js
export function normalizeAnime(record = {}) {
  return {
    id: record.mal_id,
    title: record.title || '未命名番剧'
  }
}
```

## 5. 网络请求规范

- 页面不得直接写大量 `uni.request`。
- 所有接口请求先放入 `api/`。
- 通用请求能力放入 `utils/request.js`。
- 接口函数只返回页面需要的数据结构。
- 请求失败必须显示中文错误提示。
- 避免重复并发请求，例如加载更多时必须判断 `loading` 状态。

## 6. Pinia 与持久化规范

- 全局状态统一放在 `stores/`。
- 收藏、想看、偏好等需要持久化的数据必须同步到 `uni.storage`。
- store 中提供明确 action，例如：

```js
loadFavorites()
saveFavorites()
addFavorite(item)
removeFavorite(id)
toggleFavorite(item)
isFavorite(id)
```

- 页面不直接操作 storage，必须通过 store。

## 7. 样式规范

- 样式使用 `rpx`，适配移动端显示。
- 页面背景、卡片、按钮、列表间距保持统一。
- 卡片圆角不超过 `8rpx`，除非有明确设计原因。
- 不使用过度装饰性的渐变、光斑或大面积单一色调。
- 文本必须保证不溢出、不重叠。
- 列表项、按钮、固定格式 UI 要有稳定尺寸，避免加载数据后布局跳动。
- 页面内容优先真实可用，不做营销式首页。

## 8. 中文文案规范

固定 UI 文案必须使用中文，例如：

```text
首页
搜索
想看
番剧详情
暂无评分
加载中...
没有更多了
网络请求失败，请稍后重试
```

接口返回的番剧标题、简介可以保留原始语言，不强制翻译。

## 9. 测试与验证规范

可测试的纯逻辑必须优先写测试。

- 工具函数、数据归一化、状态操作优先添加自动化测试。
- 修改代码后至少运行：

```bash
npm test
```

- 修改 `.vue` 文件后应检查单文件组件能否解析。
- 涉及接口时，应至少验证一次真实接口可访问。
- 涉及 H5 页面时，最终需要在 HBuilderX 浏览器预览中确认交互。

## 10. 禁止事项

- 禁止纯静态 mock 代替真实 API。
- 禁止在多个页面复制同一段接口请求逻辑。
- 禁止把页面写成巨型文件后再重复粘贴。
- 禁止新增无用依赖。
- 禁止为了样式效果牺牲可读性和交互可用性。
- 禁止把用户未要求的功能塞进当前任务。

## 11. 提交前检查清单

提交或交付前确认：

- 页面固定文案为中文。
- 至少运行一次测试。
- 新增接口经过封装。
- 可复用 UI 已抽成组件。
- 收藏等持久化功能刷新后仍可用。
- 没有无关文件和调试输出。
- 当前任务要求全部覆盖。
